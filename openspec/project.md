# Project Context

## Purpose
KnowsRootsAssistant is a hierarchical RAG (Retrieval-Augmented Generation) system for academic paper analysis with two-layer retrieval:
- **Layer 1 (L1)**: Paper-level retrieval using abstract embeddings
- **Layer 2 (L2)**: Chunk-level retrieval for precise context extraction

The system enables users to query academic literature with natural language and receive accurate, contextually relevant answers generated by LLMs.

## Tech Stack
- **Python 3.10+**: Core language
- **LangChain**: RAG framework and document processing
- **Ollama**: Local LLM inference (Gemma 3, BGE embeddings)
- **FAISS**: Vector similarity search (Layer 1)
- **sentence-transformers**: Cross-Encoder re-ranking (Layer 2 - in progress)
- **SQLite**: Document storage and metadata
- **Flask/FastAPI**: API layer (system_api)

## Project Conventions

### Code Style
- **PEP 8** compliance with 4-space indentation
- Type hints required for all public functions and methods
- Docstrings: Google style with Args, Returns, Raises sections
- Logging: Use Python `logging` module with appropriate levels (DEBUG, INFO, WARNING, ERROR)
- File naming: Snake_case for modules (e.g., `layer2_vectorstore.py`)
- Class naming: PascalCase (e.g., `HierarchicalRAGSystem`)

### Architecture Patterns
- **Hierarchical Retrieval**: Two-stage search to balance speed and precision
- **Dynamic Subindices**: On-the-fly index creation for filtered searches
- **Confidence-Based Expansion**: Adjust context size based on retrieval confidence
- **Modular Components**: Each subsystem (L1, L2, expander, evaluator) is independently testable
- **Configuration-Driven**: Behavior controlled via `HIERARCHICAL_RAG_CONFIG` dictionary

### Testing Strategy
- **Unit tests**: Test individual components in isolation (e.g., `test_layer2_vectorstore.py`)
- **Integration tests**: Test component interactions (e.g., `test_hierarchical_integration.py`)
- **Component tests**: Test specific features end-to-end (e.g., `test_hybrid_search.py`)
- **Test data**: Use small sample PDFs in `test_data/` directory
- **Assertions**: Verify both functionality and performance (latency, accuracy)

## Domain Context

### RAG Terminology
- **Retrieval**: Finding relevant documents/chunks from a corpus
- **Generation**: Using LLM to synthesize answers from retrieved context
- **Bi-Encoder**: Separate encoding of query and documents, fast but less precise
- **Cross-Encoder**: Joint encoding of query+document pairs, slow but highly precise
- **Re-ranking**: Scoring and re-ordering retrieved candidates for relevance
- **Topic Drift**: When retrieval returns results for only some concepts in multi-concept queries

### System Components
- **Abstract Extractor**: Extracts paper abstracts for Layer 1 indexing
- **Layer1VectorStore**: FAISS index of paper abstracts
- **Layer2VectorStore**: Currently FAISS (being upgraded to Cross-Encoder re-ranking)
- **HybridRetriever**: Combines semantic (vector) and keyword (BM25) search
- **ConfidenceEvaluator**: Determines if retrieved results are sufficient
- **ContextExpander**: Adds surrounding chunks based on confidence scores
- **IndexManager**: Handles incremental updates and backups

### Current Challenges
- **Multi-concept queries**: L2 FAISS struggles with "A AND B" type queries (e.g., "deep learning in pedestrian flow")
- **Topic drift**: L2 returns chunks relevant to dominant concept, ignoring constraints
- **Solution in progress**: Replace L2 FAISS with Cross-Encoder re-ranking (see `upgrade-layer2-reranking` change)

## Important Constraints
- **Local-first**: System runs entirely on local hardware (no cloud APIs)
- **Chinese language support**: Primary user base queries in Traditional/Simplified Chinese
- **Real-time inference**: Latency must be acceptable for interactive use (<5s for L2)
- **GPU optional**: System must work on CPU, but GPU strongly recommended for embeddings/re-ranking
- **Incremental updates**: Must support adding new papers without full re-indexing

## External Dependencies
- **Ollama service**: Must be running locally for LLM and embedding inference
- **Pre-trained models**: 
  - `BAAI/bge-base-zh-v1.5` (or similar) for embeddings
  - `BAAI/bge-reranker-base` for Cross-Encoder re-ranking (new)
  - `gemma3:12b` or similar for LLM generation
- **PDF files**: Corpus stored in `./data/` directory
- **Vectorstore persistence**: Indices stored in `./vectorstore/` directory
